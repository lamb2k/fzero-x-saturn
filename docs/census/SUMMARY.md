# G1.1 closure census

Generated by `tools/census/closure.py` from the pinned decomp
(`Zorkats/fzerox` `b944a41`), preprocessed as stock US rev0 with `PORT` and
`EXPANSION_KIT` undefined. The full table is [closure.tsv](closure.tsv), with
one row per function: file, lines, root, call depth, tier, float signal,

Tier HOST, static analysis. The float column is a lexical signal (float
literals, `f32` declarations, float math calls), not an operation count.
G1.3 counts operations from an instrumented run.

## Game mode and tick order, from source

- **Mode:** `GAMEMODE_TIME_ATTACK` with one player sets `gTotalRacers = 1`
  (`src/game/racer.c:2061`). That is the one-racer race; no new mode is
  needed. Its ghost recording and replay paths are OUT.
- **Tick:** `Race_Update` (`src/overlays/ovl_i2/race.c:132`) runs, in order:
  `Menus_Update`, `Effects_Update`, **`Racer_Update`**, `Camera_Update`,
  `Background_Update`, `Course_Update`, `func_80074844`. The controllers are
  read before it in the game loop (`src/sys/controller.c`).
- **Racer step:** `Racer_Update` → `Racer_UpdateMovement` →
  `Racer_UpdateFromControls(racer, controller)`, then the track-shape handler
  from the table `D_800CF4B8[shape](racer)`.

The tick closure is dominated by `Racer_UpdateFromControls` (1,750 lines),
`Racer_Update` (619), the eight track-shape handlers (`func_8008EC98` pipe
215, `func_8008FC80` half-pipe 201, `func_8008F550` cylinder 178,
`func_80090568` borderless road 123, and smaller), the track query
`func_8009EBEC` (165), `Racer_UpdateRacerPairInfo` (138) and
`Racer_ReceiveDamage` (105). `Racer_HitWall` is 62 lines.

The plan sized the racer port at "about 1,750 lines" for
`Racer_UpdateFromControls` alone; the full tick closure is about 2.5 times
that. Shapes that Mute City 1 does not use (G1.6 course census) drop out:
the eight shape handlers are 750 of the 4,450 TICK lines, and the road and
walled-road ones are 3 lines each. A road-and-walled-road course leaves about
3,700 lines.

## Fork hooks

- Stock build: **0** fork-hook calls in the closure. The fork's 118 hook
  lines inside tick functions (55 in `Racer_UpdateFromControls`, 28 in
  `Racer_Update`) all compile out.
- **Control:** the same census with `--define PORT` finds **91** fork-hook
  calls in the closure (`CVarGetInteger`, `gdx_*`, `GdxCustomGrid_*`). The
  hooks matter, and they are off in the reference. The trace-hash version of
  this control lands with the reference harness (G1.2).

## Flags

- `NON_MATCHING` in the closure: `func_8009DB28` (init, OFFLINE) and
  `Matrix_SetAxisRotation` (init, OUT). Neither is in the tick. They are
  equivalent by claim, not by bytes; the reference runs them as written.
- Indirect calls, all resolved through tables: `D_800CF4B8` (track shapes) from
  `Racer_Update` and `Racer_UpdateFromControls`, and the segment-chunk tables
  from `func_800A1954` (init).
- Out of the closure by design: `Cpu_GenerateInputs` (`src/overlays/ovl_i3/cpu.c`),
  used for CPU racers and for the player after the finish. The POC coasts after
  the finish instead.
- Tick calls to presentation (`Audio_*`, `Effects_Spawn*`, `Hud_Trigger*`) are
  stubbed in the reference and become native events later.

## Simulation state

TICK functions write 40 globals (in `closure.tsv`). The racer state is
`gRacers[0]`. The race state is in `gRaceIntroTimer`, `gRacersFinished`,
`gPlayerLives`, `sRaceFrameCount` and the lap and position fields. The random
streams are `gRandSeed1/2` and `gRandMask1/2`, so `Math_Rand1/2` must be
reproduced exactly.
