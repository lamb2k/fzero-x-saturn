# Reference harness (G1.2)

The judge for the fixed-point port. It is the original, stock US rev0 race code from the
decomp (`upstream/G-Diffuser/decomp`, with the fork's `PORT` and `EXPANSION_KIT` hooks
compiled out), built natively as a 32-bit binary with SSE binary32 float. It is never part
of the Saturn or web builds.

```
ref/build.sh [gcc|clang] [-O0|-O2]     # -> ref/build/<cc><opt>/fzx-ref
ref/check.sh                           # the G1.2 gate; --update rewrites expected/fixture.hashes
fzx-ref --course RECORD --byte-order big|little --inputs SCRIPT [--rom ROM] [--ticks N] [--trace OUT]
```

Needs a 32-bit capable compiler (`gcc-multilib`; clang uses the same libraries).

## What runs

`bridge.c` sets up the race as the menus leave it: Time Attack, one player, Blue Falcon,
engine slider in the middle. It then calls the `Race_Init` steps that set simulation
state, in order: `Course_Init`, the grid set-up `func_i3_80116C4C` and `Racer_Init`. Each
tick it calls the original `Controller_UpdateInputs` and `Racer_Update`. The boot-time sine
table comes from the original `Math_SinTableInit`.

Hardware is reached in three places only (`hooks.c`, `overrides.h`):

- **Course record.** The original loader DMAs one 0x7E0-byte `CourseDataDisk` record into
  the course context. `osEPiStartDma` serves those chunks from `--course` and skips every
  other ROM read (textures, models, sound).
- **Machine constants.** `Racer_InitMachineStats` reads them through `ROM_READ` from the
  first 4 KB of the cartridge. They come from `--rom` (the owner's ROM, local only) or, in
  CI, from a fixed arbitrary byte pattern. The CI fixture's constants carry no meaning:
  on the fixture, the machine loses all its energy within a few wall contacts.
- **Pad.** `osContGetReadData` provides pad 0 from the input script. Pads 1 to 3 are
  unplugged.

Every other undefined symbol is a stub generated by `gen_stubs.py`: a function returning
zero (typed float where the decomp declares it so), or zeroed storage. The build prints a
count of the stubs. The host C library and libm are never stubbed.

## Inputs and traces

Each line of an input script is `<ticks> <buttons> [stick_x stick_y]`. Buttons are `-`
for none, or names joined by `+`: `A B Z S L R CU CD CL CR`. The race intro takes 460
ticks, so every script starts with that many ticks before the action.

The trace (v1) has one tab-separated line per tick: the inputs, then the racer's state
subset with each float as exact binary32 hex, then position and speed in decimal for
reading. The last line is `hash`, an FNV-1a 64 over every traced value and input.

## The gate (`check.sh`)

1. **Determinism.** gcc and clang, each at -O0 and -O2, give the same hash for T01 to T10.
2. **Byte order.** A little-endian copy of the same course record gives the same hash.
3. **Regression.** The hashes match `expected/fixture.hashes`.
4. **Control.** Flipping one bit inside a machine-constant field moves the T02 hash.

`-fno-unsafe-math-optimizations` is required in addition to `-fno-fast-math`. Without it,
clang 18 at -O1 and above rewrites float code in `course.c`, and the start position drifts
by one ulp. The four-way check found this.

`fixture_course.py` writes the synthetic course: an authored 8-point oval, not game data.
No ROM, ROM-derived record or trace taken on a retail course is ever committed.
